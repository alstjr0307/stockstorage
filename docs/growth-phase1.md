# 성장 개선 1차 — 2026-09-12

## 반영한 사용자 흐름

- 홈 인사 바로 아래에 관심종목을 배치한다. 저장한 종목이 없으면 검색 버튼을 표시하고, 저장한 개수만큼 행을 표시한다. 홈을 당겨 새로고침하면 관심종목 시세도 새로 조회한다.
- AI 분석의 요약·점수 다음에 관심종목 저장과 가격 알림 버튼을 제공한다. 기존 저장 상태를 읽기 전에는 저장 버튼을 비활성화하고, 저장 중 연속 클릭을 막는다. 실패하면 재시도할 수 있다.
- 일반 종목 상세에서 비회원이 저장 버튼을 누르면 로그인 화면을 연다. 로그인 후 같은 종목의 저장을 이어서 처리한다. 같은 종목을 다시 저장해도 최초 addedAt을 유지한다.
- AI 텍스트·이미지 공유와 일반 종목 텍스트 공유에 `/stock/{market}/{ticker}` 링크를 넣는다. 기존 추천주·시황 링크는 유지한다.
- 공개 페이지는 `market_feature_stocks`에 공개된 자료만 서버에서 렌더링한다. 기준일을 표시하고 실시간 시세와 구분한다. 자료가 없으면 상세로 이동하는 안내를 제공한다. 개인별 AI 결과나 메모는 읽지 않는다.
- 웹 상세로 이동할 때 시장과 종목 코드를 유지한다. Android와 iOS 연결 설정에 `/stock/` 경로를 추가한다. iOS 연결 파일의 임시 식별자는 Xcode 프로젝트의 Team ID와 Bundle ID로 수정했다.

## 측정 이벤트

모든 신규 이벤트에 `ticker`, `market`, `source`를 기록한다. 전송 실패가 저장이나 화면 이동을 실패시키지 않도록 처리했다.

| 이벤트 | 의미 |
|---|---|
| analysis_view | AI 결과를 화면에 불러옴. source=cache/generated |
| stock_saved | 관심종목 저장 작업 성공. source=ai_result/stock_detail. 최초 저장만의 이벤트는 아님 |
| price_alert_start | 로그인한 사용자가 알림 설정 흐름에 진입. 한도에 막힌 경우도 포함 |
| price_alert_created | 알림 문서 저장 성공 |
| stock_share_open | 공유 UI 호출. 공유 완료나 상대방 전달을 의미하지 않음 |
| stock_share_landing | 공유 링크에서 네이티브/웹 상세 화면으로 이동. 공개 HTML 페이지 단독 조회는 포함하지 않음 |
| watchlist_stock_open | 홈 관심종목 행에서 상세를 열음 |

기존 `add_to_wishlist`와 신규 `stock_saved`를 합산하면 중복될 수 있다. 신규 분석 후 저장 흐름은 `analysis_view` 뒤 `stock_saved(source=ai_result)`가 발생한 고유 사용자로 측정한다. GA4에서 사용자별 순서가 있는 퍼널을 구성해야 하며, 두 이벤트의 단순 합계 비율을 전환율로 쓰지 않는다.

관심종목 자체를 여러 기기에서 이미 저장했거나 해제 후 다시 저장한 경우도 `stock_saved`에 포함된다. 최근 이벤트 사용자 수와 현재 저장 계정 수는 다른 지표다. 알림 문서 생성 수는 푸시 수신 성공 수가 아니다.

## 검증과 출시

- Flutter 저장·링크·로그인·검색 관련 25개 테스트 통과. 후속 보완 후 저장·링크·웹 셸 8개 재검증 통과(기존 25개와 중복).
- Node 공유 페이지 테스트 6개 통과: URL 검증, HTML 삽입 방지, 종목을 유지하는 CTA, 데이터 없는 상태, 공개 컬렉션만 조회, 잘못된 요청의 DB 접근 차단.
- 공개 운영 자료를 읽기 전용으로 로컬 페이지에 표시하고 브라우저 배치를 확인했다.
- 최종 웹 빌드에서 공유 URL의 삼성전자(KS/005930) 상세 이동, 비회원 관심종목 버튼 활성화, 클릭 후 로그인 화면 표시를 브라우저로 확인했다. 실제 계정 로그인·저장은 하지 않았다.
- 웹 릴리스 빌드와 Android debug APK 빌드 통과. 변경 파일의 정적 분석에는 기존 미사용 선언·비동기 context 경고가 남아 있으며 신규 오류는 없다.
- 운영 데이터 변경, 푸시 발송, 실제 로그인/저장 테스트, 유료 AI 생성, 운영 배포는 수행하지 않았다.

출시 시 새 `stockLanding` 함수와 landing hosting rewrite, 웹 빌드를 먼저 반영한 뒤 모바일 업데이트를 배포한다. 앱만 먼저 배포하면 새 공유 주소가 아직 동작하지 않을 수 있다. iOS/Android의 실제 설치 앱 링크 이동은 기기에서 확인해야 한다. iOS 빌드·서명은 macOS에서 수행해야 한다.
