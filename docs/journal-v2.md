# 최신 로직 수정

현재 동시 저장 보호, Firestore 오류 보정 및 배포/롤백 조건은 [journal-logic-fix.md](journal-logic-fix.md)를 먼저 확인한다. 아래는 기존 UI 복원 시점의 기록이다.

# 매매일지 변경 및 복구

## 현재 적용 화면

별도로 만들었던 V2 종목 카드 화면 대신 원래 `TradingJournalTab`의 날짜별 화면을 기본으로 복원했다. V2 화면·전환 위젯 소스는 남겨 두었지만 현재 앱 진입점에서는 사용하지 않는다. 따라서 이전의 화면 전환 메뉴와 `JOURNAL_V2` 빌드 옵션은 현재 기본 화면에 적용되지 않는다.

- 원래 날짜 이동, 일별 원화/달러 매수·매도 합계, 매매 카드, 차트, 보유 현황, 입력 폼을 유지한다.
- 날짜 제목에 달력 선택 안내를 붙이고 기록 없는 날짜도 선택할 수 있게 했다. 빈 날짜는 다른 날짜로 바뀌지 않고 빈 상태를 표시한다.
- 이전/다음은 실제 거래가 있는 날짜로 이동한다.
- 카드 외곽 여백과 배경 장식만 정리했다. 매수 배지에 첫 매수/물타기/불타기를 표시하며 추가 매수의 평단 변화를 보여준다.
- 기존 폼에서도 거래일을 수정할 수 있다. 날짜만 선택하면 기존 시각의 정밀도는 유지한다.

## 계산과 데이터 보호

기존 화면의 평단·보유원가·실현손익 계산에 공통 이동평균 계산기를 연결했다. 원본 거래를 다시 저장하거나 마이그레이션하지 않는다. 신규·수정 저장과 삭제는 `JournalV2Repository`의 서버 재확인, 이후 매도 수량 검증, 기존 필드 보존 경로를 사용한다. 검증 실패는 화면에 안내한다. 같은 기기 중복 저장은 차단한다.

사용자가 수정한 거래의 가격, 수량, 거래일, 메모, 공개 여부 및 공개 전환 시각만 갱신한다. 좋아요, 소유자, 생성 시각, 기존 매수 연결 정보, 알 수 없는 추가 필드는 보존한다. 다른 기기/구버전 앱의 동시 신규 삽입까지 원자적으로 방지하는 서버 장치는 이번 범위에 없다.

## 소스 롤백

`python tools/rollback_journal_v2.py`로 검사하고, `python tools/rollback_journal_v2.py --apply`로 최초 작업 전 매매일지 진입 파일을 복원한다. 이후의 별도 수정이 있으면 체크섬이 달라 덮어쓰지 않고 중단한다. 새 파일은 삭제하지 않고 사용하지 않는 상태로 남긴다.

최초 백업: `output/journal-v2-backup/20260913-002149`.
이번 원래 UI 복원 직전 파일: `output/journal-original-ui-backup/20260913-005258/lib/screens/trading_journal_screen.dart`.

백업은 소스 백업이며 데이터베이스 백업이 아니다. 롤백이 사용자의 이후 거래 저장·삭제를 취소하지는 않는다. 운영 데이터 변경 및 배포는 수행하지 않았다.
